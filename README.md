## The problem

**High-density segmentation** means finding and outlining *every* object instance in a scene with many of them: a parked street, a dinner table, a crowd. Each object gets its own pixel mask. The count follows directly from the masks.

**Who needs it:** retail shelf auditing, crowd and traffic monitoring, warehouse and agricultural counting, and any pipeline where "how many, and where" matters more than one label for the whole image.

**Why it's hard:**

- **Occlusion and touching objects.** Neighbouring instances overlap, so their boundaries are ambiguous.
- **Non-maximum suppression assumes overlap means duplication.** In a crowd that assumption is wrong, and a detector tuned for ordinary scenes suppresses real objects.
- **Classical methods have no object prior.** Thresholding and colour clustering split pixels by intensity or colour, not by object. They merge touching objects or shatter one object into many regions.
- **IoU alone can mislead.** A method that sprays many masks can score decent overlap while getting the count badly wrong (see KMeans below).

This project measures those failure modes on COCO images with **5–50 non-crowd objects**. It then tests whether gating a relaxed second detector pass on a cheap crowding signal beats the detector alone.

## Model architecture

```mermaid
flowchart TB
    IN[Input 640×640×3] --> BB
    subgraph BB[Backbone: CSPDarknet with C2f blocks]
        P3[P3 / stride 8]
        P4[P4 / stride 16]
        P5[P5 / stride 32 + SPPF]
    end
    BB --> NK[Neck: PAN-FPN<br/>top-down + bottom-up feature fusion]
    NK --> DH[Decoupled anchor-free head<br/>box via DFL · 80 class scores]
    NK --> MC[32 mask coefficients per instance]
    NK --> PR[Proto head<br/>32 prototype masks · 160×160]
    DH --> O0["output0: 1 × 116 × 8400<br/>(4 box + 80 cls + 32 coeff)"]
    MC --> O0
    PR --> O1["output1: 1 × 32 × 160 × 160"]
    O0 & O1 --> M["mask_i = σ(Σ c_ik · P_k), cropped to box_i"]
```

**In plain English.** The **backbone** (CSPDarknet with C2f blocks) turns the image into feature maps at three scales, so both small and large objects are represented. The **neck** (PAN-FPN) mixes those scales top-down and bottom-up, so each level carries both detail and context. The **head** is anchor-free. At every location of the three grids (80² + 40² + 20² = 8,400) it predicts a box, 80 class scores and 32 mask coefficients. In parallel, a **proto head** produces 32 shared prototype masks. Each instance's mask is a sigmoid of its 32 coefficients applied to those prototypes, cropped to its box. That is how one network emits a variable number of masks.

**Loss.** Fine-tuning uses the Ultralytics YOLOv8 segmentation loss, a weighted sum of four terms (gains from the checkpoint's `train_args`):

| Term | What it penalises | Gain |
|---|---|---|
| Box (CIoU) | box overlap, centre distance and aspect-ratio error | 7.5 |
| DFL (distribution focal loss) | the box-edge distribution, which sharpens localisation | 1.5 |
| Classification (BCE) | class scores against task-aligned targets | 0.5 |
| Segmentation (per-pixel BCE) | each instance's assembled mask against its ground-truth mask, inside its box | 7.5 |

**The hybrid sits on top of the trained model and adds no new weights:**

```mermaid
flowchart TB
    IMG[Image] --> Y1[YOLO pass<br/>conf 0.25 · NMS IoU 0.45]
    IMG --> ED[Canny edge density]
    Y1 --> G{edge density > 0.08<br/>OR count ≥ 10?}
    ED --> G
    G -- no --> OUT1[Keep YOLO masks]
    G -- yes --> Y2[Relaxed YOLO pass<br/>conf 0.15 · NMS IoU 0.35]
    Y2 --> K[Keep whichever pass<br/>found more instances]
    K --> WS{Watershed regions<br/>> 1.2 × detections?}
    WS -- yes --> BL[count = 0.8·YOLO + 0.2·watershed]
    WS -- no --> OUT2[Final masks + count]
    BL --> OUT2
```

The gate measures crowding with **Canny edge density, not the detector's own count**. If the detector has already missed the crowd, its count can't be what tells you a crowd is there.

## Evaluation

**Metrics**, all defined once in `src/metrics.py`:

- **Mean instance IoU.** Class-agnostic, with greedy one-to-one matching between predicted and ground-truth masks. Unmatched ground-truth objects score 0, so missing objects is penalised.
- **Count accuracy (±3).** The share of images where |predicted − true count| ≤ 3.
- **Count MAE.** Mean absolute counting error per image.
- **Latency.** Median and interquartile range after warm-up, never a mean over a cold start.

| Method | Type | Mean IoU | Count acc. (±3) | MAE | Median latency |
|---|---|---|---|---|---|
| Watershed | Classical | 0.065 | 28% | 8.66 | 13 ms <sub>(IQR 11–17)</sub> |
| KMeans (k=5) | Classical | 0.252 | 0% | 114.86 | 88 ms <sub>(IQR 70–110)</sub> |

| Hybrid (density-aware) | Hybrid | **0.456** | **64%** | **3.30** | 62 ms <sub>(IQR 54–71)</sub> |

The table above is generated from `results/metrics/unified_results.json` by `scripts/update_readme.py`. Running `--check` fails if it goes stale.

![Comparison of the four methods](results/figures/comparison.png)

**How to read it:**

- **The hybrid improves counting much more than mask quality.** Compared with YOLO alone, count accuracy goes from 52% to 64% and MAE from 4.28 to 3.30. Mean IoU moves only from 0.429 to 0.456, because the hybrid's masks still come from a YOLO pass.
- **KMeans shows why IoU alone isn't enough.** It reaches 0.252 IoU while getting the count right on *zero* images. It emits **127.5 masks per image against 12.64 real objects**, so greedy matching finds overlap by volume.
- **Watershed under-counts.** It averages 4.22 masks per image, because Otsu thresholding assumes a bimodal intensity histogram that natural photos don't have.

![Predicted vs true count](results/figures/count_scatter.png)

### Ablation: which half of the hybrid does the work?

`src/ablation.py` splits the hybrid's gain between its two mechanisms:

| Mechanism | Images it fired on | Count error removed |
|---|---|---|
| Density-gated relaxed detector pass | 41 / 50 | **46 objects** |
| Watershed cross-check | 4 / 50 | **3 objects** |

The classical cross-check contributes **6.1%** of the improvement. So the method is more accurately described as **density-aware two-pass detection with a marginal classical correction**. On the 9 images where the gate didn't fire, the hybrid's MAE (2.56) is identical to YOLO's, so the gate costs nothing when it isn't needed.

## Getting started

Tested with **Python 3.12**. The NumPy pin (2.0.2) has no wheels for Python 3.13.

```bash
git clone https://github.com/Zakuroooo/high-density-object-segmentation.git
cd high-density-object-segmentation
python3.12 -m venv .venv
.venv/bin/pip install torch torchvision      # pick the wheel for your CUDA / CPU / MPS
.venv/bin/pip install -r requirements.txt
```

**Get COCO val2017** (about 1 GB of images plus the annotations):

```bash
mkdir -p data && cd data
curl -LO http://images.cocodataset.org/zips/val2017.zip
curl -LO http://images.cocodataset.org/annotations/annotations_trainval2017.zip
unzip -q annotations_trainval2017.zip -d annotations
mkdir -p images && unzip -q val2017.zip -d images && cd ..
```

**Train, evaluate, regenerate:**

```bash
export PYTHONPATH=src
.venv/bin/python src/prepare_yolo_data.py   # seeded dense subset + YOLO labels
.venv/bin/python src/train.py               # fine-tune (GPU recommended)
.venv/bin/python src/evaluate.py            # all four methods, one run
.venv/bin/python src/ablation.py            # decompose the hybrid's gain
.venv/bin/python src/figures.py             # figures from the results file
.venv/bin/python scripts/update_readme.py   # regenerate the results table
```

The fine-tuned checkpoint is committed, so `evaluate.py` doesn't need retraining. With no local GPU, `notebooks/colab_pipeline.ipynb` runs the whole pipeline on a free Colab T4.

**Run the demo locally:**

```bash
python3 -m http.server 8099 --directory space-static
# open http://localhost:8099  (ONNX Runtime Web loads from the jsDelivr CDN)
```

<sub>Verification for this README: on a CPU-only machine without COCO access, the install succeeded. `ablation.py`, `figures.py` and both `--check` scripts ran and reproduced the committed outputs. `train.py`, `prepare_yolo_data.py` and `evaluate.py` started and stopped at the missing-data check, as expected. The static demo served all its assets. Full training and evaluation were not re-run.</sub>

## Key decisions and challenges

| Challenge | Fix |
|---|---|
| An earlier version printed numbers from two different runs (different models, sample sizes and devices) as one table | A single harness (`src/evaluate.py`) scores every method on one test set in one run. All tables and figures are generated from its output, and `--check` scripts catch drift. |
| The classical baselines returned only a count, so the IoU numbers published for them had no masks behind them | Both baselines now return instance masks, scored by the same function as YOLO |
| The subset was the 500 lowest COCO image IDs, which is a biased sample | A seeded uniform sample from all 2,463 dense images, with the split IDs committed |
| A mean latency was dominated by one 12.7 s cold start | Warm-up before timing, with median and IQR reported |
| A blanket `*.pt` gitignore meant the trained weights were lost | The checkpoint is committed (`weights/`), with a `.gitignore` exception |
| Training on an 8 GB M2 could only fit 512 px / batch 2 and swapped heavily | Moved training to a Colab T4 at 640 px / batch 16 |
| Crowds suppress real detections through NMS | A cheap Canny edge-density gate triggers a relaxed second pass only on crowded scenes |
| Pixel-clustering baselines have no class labels | Every method is scored class-agnostically, so all four share one scale |
| The demo needed to be free to host and fast to start | The model was exported to ONNX and post-processing ported to JS, so it runs in the browser on a static Space |

## Limitations and future work

**Limitations**

- **The test split is 50 images.** That's enough to show the classical-versus-deep gap, but not enough to prove the hybrid-versus-YOLO margin. Treat that margin as a direction.
- **Fine-tuned on COCO, evaluated on COCO.** The base model was already COCO-pretrained, so this measures adaptation to dense scenes, not generalisation to a new domain.
- **Class-agnostic scoring.** A correct mask with the wrong label still counts as a hit.
- **Single-polygon labels.** COCO objects annotated as several disjoint polygons keep only their largest part, because of the YOLO label format.
- **Mosaic augmentation never ran** (see Training setup), and the model trained for only 10 epochs. The validation mask losses rose over training (see the training curves), so the checkpoint is far from tuned.
- **The browser demo omits the watershed cross-check.** It would need OpenCV compiled to WebAssembly, for a component the ablation shows contributes 6.1% of the gain. The demo also uses single-threaded WASM, so it's slower than the GPU latencies above.
- **The hybrid can raise its count without adding masks.** When the watershed blend fires, the count and the number of drawn masks can differ.

**Future work**

- A larger, cross-validated test split to put confidence intervals on the hybrid's margin.
- Longer training with mosaic actually enabled (`close_mosaic` < `epochs`).
- Evaluation on a genuinely dense, out-of-domain dataset, such as retail-shelf or crowd-counting benchmarks.
- Class-aware COCO mAP for the deep methods alongside the class-agnostic comparison.
- Learning the gate thresholds on the validation split instead of using fixed values.
